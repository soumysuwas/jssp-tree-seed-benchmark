# results/timing/

Wall-clock timing runs. Time is **solve time** (elapsed seconds to run the search under a fixed
`MaxFEs = D×1000` budget), not training time — these are not learned models.

| File | Contents | Regenerated by |
|---|---|---|
| `timing_serial.csv` | DTSA-core, one job at a time, per-instance elapsed seconds | `dtsa/run_timing.py serial` |
| `timing_contention.csv` | DTSA-core elapsed vs number of concurrent jobs | `dtsa/run_timing.py contention` |
| `atsa_timing_serial.csv` | ATSA, one job at a time, per-instance elapsed seconds | `dtsa/run_atsa_timing.py serial` |
| `atsa_timing_contention.csv` | ATSA elapsed at 1 / 8 / 24 concurrent jobs | `dtsa/run_atsa_timing.py contention` |
| `timing_recheck.csv` | A re-measurement spot-check | `dtsa/run_timing_recheck.py` |

**Fair-basis note.** The ATSA-vs-DTSA per-run time gap reflects the implementation (ATSA's loop is
Numba-compiled; DTSA-core's is plain NumPy for readability), **not** the algorithms. The like-for-like
basis is the identical evaluation budget, not wall-clock. See the DTSA report §5.6.

Run timing with a quiet machine and `--jobs 1` for the serial numbers.
